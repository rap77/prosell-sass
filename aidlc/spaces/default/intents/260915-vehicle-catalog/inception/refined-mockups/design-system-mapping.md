# Design System Mapping — Catálogo Canónico de Vehículos para Facebook

Confirma qué de `mockups.md`/`interaction-spec.md` reutiliza componentes ya existentes en la plataforma vs. qué es genuinamente nuevo. Sin patrón visual nuevo (confirmado en Rough Mockups, reconfirmado en Refined Mockups Q1/Q2).

| Elemento de mockup                                                 | Componente existente reutilizado                                                                                                                                 | Extensión necesaria                                                                                                                                                                                                  |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Selects canónicos de categoría/atributo (Screen 1)                 | `GenericFormFields` / `GenericProductForm` (`apps/web/src/components/...`)                                                                                       | Ninguna estructural — mismo componente de select ya usado hoy para otros atributos de vehículo; solo cambia la fuente de las `options` (catálogo canónico reconciliado, FR1)                                         |
| Ícono de ayuda "(i)" + tooltip en campo sin match (AC1.1.2)        | Ninguno existente — primer uso de este patrón puntual en la plataforma                                                                                           | Nueva: variante de campo con tooltip/ícono de ayuda adjunto (documentada en `interaction-spec.md` como `CanonicalSelectField`, prop `unmatched`)                                                                     |
| Estado de error inline por campo (AC1.1.3)                         | Patrón de error inline ya usado por `GenericFormFields` para validación de campos requeridos                                                                     | Ninguna — mismo mecanismo de error ya vigente, sin estilo nuevo                                                                                                                                                      |
| Campos de ubicación ciudad/estado con badge de herencia (Screen 2) | Par de inputs de texto "Ciudad"/"Provincia o Estado" ya usado en `OrganizationFormFields.tsx` (`apps/web/src/components/admin/`) para el default de organización | Nueva: badge "Heredado de organización" (documentado en `interaction-spec.md` como `ProductLocationFields`, prop `isInherited`) — el par de campos en sí ya existe, solo se aplica ahora también a nivel de producto |
| Editor de schema de categorías (US1.2, Platform Admin)             | `category-schema-editor.tsx` ya existente, sin cambio visual                                                                                                     | Ninguna — solo cambia la fuente de las `options` (catálogo canónico reconciliado, FR1), ver nota de cobertura en `mockups.md`                                                                                        |
| Botones Cancelar/Guardar (ambas pantallas)                         | Patrón de botones ya vigente en toda la plataforma                                                                                                               | Ninguna                                                                                                                                                                                                              |
| Toast de confirmación al guardar                                   | Sistema de toasts ya vigente en la plataforma                                                                                                                    | Ninguna                                                                                                                                                                                                              |

## Resumen

Dos extensiones puntuales sobre patrones existentes (`CanonicalSelectField` sobre `GenericFormFields`, `ProductLocationFields` sobre el par ciudad/estado ya usado por `OrganizationFormFields.tsx`) — ningún componente nuevo desde cero, ningún patrón visual (color, tipografía, espaciado) fuera del sistema de diseño ya vigente. Consistente con la decisión ya afirmada en Rough Mockups y reconfirmada en Q1/Q2 de esta etapa.
